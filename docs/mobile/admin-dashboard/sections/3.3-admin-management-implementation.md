## API Integration

### Endpoints Used

1. **GET /api/admin/GET/existing-admins**
   - Fetches list of current admins
   - Returns: `{ admins: AdminUser[] }`

2. **GET /api/admin/GET/search-users?email={email}**
   - Searches for users by email
   - Returns: `{ users: SearchResultUser[] }`

3. **POST /api/admin/POST/admin-mgmt-add**
   - Adds admin privileges to a user
   - Body: `{ userId: string }`
   - Returns: `{ message: string }`

4. **POST /api/admin/POST/admin-mgmt-remove**
   - Removes admin privileges from a user
   - Body: `{ adminId: string }`
   - Returns: `{ message: string }`

## User Flows

### Add Admin Flow

1. User enters email in search field
2. User taps "Search" button
3. System searches for users matching email
4. Search results display with "Add Admin" buttons
5. User taps "Add Admin" button
6. System checks if user is already admin
7. If not admin: confirmation dialog appears
8. User confirms action
9. System adds admin privileges
10. Success notification shown
11. Admin list refreshes automatically
12. Search is cleared

**Error Scenarios:**
- Invalid email format → Show validation error
- User not found → Show "No users found" message
- User already admin → Show "Already Admin" badge (prevent addition)
- API error → Show error message with retry option

### Remove Admin Flow

1. User views admin list
2. User taps "Remove Admin" on an admin card
3. Confirmation dialog appears
4. User confirms removal
5. System removes admin privileges
6. Admin removed from list (optimistic update)
7. Success notification shown

**Error Scenarios:**
- API error → Show error message, re-fetch list
- Network error → Show error with retry option
- Permission denied → Show appropriate error message

## Known Issues & Limitations

4. No admin role differentiation

- For auto-search: Intentional to reduce API calls
