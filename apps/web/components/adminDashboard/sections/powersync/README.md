# PowerSync Service Admin Section

This admin dashboard section provides monitoring and status tracking capabilities for the PowerSync real-time sync service.

**Last Updated:** January 1, 2026  
**Related Documentation:** `docs/power-sync/01_01_2026_jwt_kid_fix.md`, `docs/power-sync/01_01_2026_jwt_sub_claim_fix.md`

## Features

### 📊 Overview Tab
- **Service Status**: Real-time health status (healthy/starting/error)
- **Uptime Monitor**: Time since last activity
- **Service Started**: Whether the service has fully started
- **Response Time**: Health check response time in milliseconds

### 🔄 Replication Tab
- **Replication Status**: Current sync state
- **Ready State**: Whether service is ready to accept connections
- **Started State**: Whether service startup is complete
- **Last Activity**: Timestamp of last sync activity

### 🔧 Details Tab
- **Service Configuration**: Internal URL and endpoint details
- **WebSocket Endpoint**: External WebSocket URL for mobile clients (`wss://ws.emr.fajr.org`)
- **Health Check Endpoint**: API route for health monitoring (`/api/powersync/health`)
- **Token Endpoints**: Web (`/api/auth/powersync-token`) and Mobile (`/api/auth/mobile-login`)
- **JWT Configuration**: Key ID (`fajr-emr-key`), Algorithm (HS256)
- **Advanced Information**: Raw health response JSON
- **Troubleshooting Guide**: Common issues and solutions including JWT authentication errors

## Troubleshooting

### Service Not Responding
**Symptoms:**
- "Service Unavailable" error
- Timeout errors
- No health data

**Solutions:**
1. Check PowerSync container is running:
   ```bash
   docker ps | grep powersync
   ```
2. Verify environment variables:
   ```bash
   POWERSYNC_SERVICE_URL=http://powersync:6061
   ```
3. Check Docker network connectivity
4. Review service logs:
   ```bash
   docker logs <powersync-container-name> --tail 100
   ```

### JWT Authentication Errors

#### Error: Missing required claim 'sub'
**Symptoms:**
- Mobile app shows: `[PSYNC_S2101] JWT payload is missing a required claim "sub"`
- Connection fails immediately after login
- PowerSync keeps retrying every ~5 seconds

**Root Cause:**
JWT tokens generated by `/api/auth/mobile-login` don't include the `sub` (subject) claim required by PowerSync.

**Solutions:**
1. **Fix Applied (Jan 1, 2026):** The mobile-login endpoint now includes `sub: user.id` in JWT payload
2. **Users must log out and back in** to get fresh tokens with the `sub` claim
3. Old cached tokens without `sub` will continue to fail
4. Force quit app completely if needed to clear token cache

#### Error: Signature verification failed
**Symptoms:**
- `[PSYNC_S2101] signature verification failed`
- Connection fails despite having correct `kid` header

**Root Cause:**
JWT_SECRET environment variable is base64-encoded, but `jwt.sign()` was using the base64 string directly instead of decoding it first.

**Solutions:**
1. **Fix Applied (Jan 1, 2026):** Both endpoints now decode the base64 secret:
   ```typescript
   const JWT_SECRET_BASE64 = process.env.JWT_SECRET || "";
   const JWT_SECRET = Buffer.from(JWT_SECRET_BASE64, 'base64');
   ```
2. Redeploy web application after fix
3. Users must log out and back in to get correctly signed tokens

#### Error: Could not find an appropriate key in the keystore
**Symptoms:**
- `[PSYNC_S2101] Could not find an appropriate key in the keystore`
- JWT header missing `kid` field

**Root Cause:**
JWT tokens not including the `kid` (key ID) header that PowerSync uses to identify which key to use for verification.

**Solutions:**
1. **Fix Applied (Jan 1, 2026):** Both endpoints now include `kid` in JWT header:
   ```typescript
   jwt.sign(payload, JWT_SECRET, {
     header: {
       kid: "fajr-emr-key",
       alg: "HS256",
     },
   });
   ```
2. Verify JWT_CONFIG.KID matches PowerSync JWKS configuration
3. Users must log out and back in to get tokens with `kid` header

### Service Started but Not Ready
**Symptoms:**
- `started: true` but `ready: false`
- Status shows "starting"

**Solutions:**
1. Wait 30-60 seconds for startup
2. Check for replication lock errors in logs
3. Verify PostgreSQL connection
4. Review sync rules configuration

### Slow Response Times
**Symptoms:**
- Response times >500ms
- Intermittent timeouts

**Solutions:**
1. Check database query performance
2. Monitor container resource usage
3. Review replication lag
4. Consider scaling resources

### Replication Lock Errors
**Symptoms:**
- Service logs show "PSYNC_S1003" errors
- Service fails to start properly

**Solutions:**
1. Run the cleanup script (automatic on redeploy)
2. Manually clear locks via SQL:
   ```sql
   UPDATE powersync.sync_rules SET state = 'STOPPED' WHERE state = 'ACTIVE';
   DELETE FROM powersync.locks;
   ```
3. Restart PowerSync service
4. Wait for cleanup to complete

## Environment Variables

### Web App
```bash
# PowerSync service URL (internal Docker network)
POWERSYNC_SERVICE_URL=http://powersync:6061  # Optional, defaults to this

# JWT Secret (base64-encoded, 64 bytes decoded)
JWT_SECRET=<REDACTED-generate-with-openssl-rand-base64-64>

# NextAuth Secret (different from JWT_SECRET)
NEXTAUTH_SECRET=<REDACTED-generate-with-openssl-rand-base64-32>
```

**Important:** 
- `JWT_SECRET` is base64-encoded and MUST be decoded before using with `jwt.sign()`
- Both `/api/auth/mobile-login` and `/api/auth/powersync-token` use `JWT_SECRET`
- `NEXTAUTH_SECRET` is used only by NextAuth for session management

### PowerSync Service
```bash
POSTGRES_HOST=your-postgres-host
POSTGRES_PORT=5432
POSTGRES_DB=postgres
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your-password

# JWT Secret (MUST match web app JWT_SECRET)
JWT_SECRET=<REDACTED-generate-with-openssl-rand-base64-64>

POWERSYNC_PORT=6061
```

## Integration

### Mobile App Integration
Mobile apps should connect to PowerSync via WebSocket:

```typescript
// Mobile app configuration (apps/mobile/src/config/index.ts)
PROD: {
  BASE_URL: 'https://emr.fajr.org',
  API_URL: 'https://emr.fajr.org/api',
  POWERSYNC_URL: 'https://ws.emr.fajr.org',  // SDK converts to wss://
}

// PowerSync connection
const powerSyncUrl = "https://ws.emr.fajr.org";
const connector = new PowerSyncDatabase({
  database: db,
  schema: AppSchema,
  flags: {
    enableMultiTabs: false,
  },
});

// Fetch credentials with JWT token
async function fetchCredentials() {
  const token = await getStoredToken();  // From mobile-login
  return {
    endpoint: powerSyncUrl,
    token: token,  // JWT with kid, sub, and correct signature
  };
}
```

### JWT Token Requirements
All JWT tokens must include:

**Header:**
```json
{
  "kid": "fajr-emr-key",
  "alg": "HS256",
  "typ": "JWT"
}
```

**Payload (Mobile):**
```json
{
  "sub": "user-uuid-here",      // REQUIRED - User ID
  "id": "user-uuid-here",        // User ID (redundant)
  "email": "user@example.com",
  "accountType": "Doctor",
  "isAdmin": true,
  "firstName": "John",
  "lastName": "Doe",
  "doctorSpecialty": [],
  "iat": 1767285848,
  "exp": 1768495448             // 14 days from issue
}
```

**Payload (Web):**
```json
{
  "sub": "user@example.com",    // REQUIRED - User email
  "user_id": "user@example.com",
  "email": "user@example.com",
  "iat": 1767285848,
  "exp": 1767372248             // 24 hours from issue
}
```

## JWT Configuration

### JWT Config File
**Location:** `apps/web/lib/jwt-config.ts`

```typescript
export const JWT_CONFIG = {
  KID: "fajr-emr-key",
  ALG: "HS256" as const,
  MOBILE_TOKEN_EXPIRY: "14d",
} as const;
```

### PowerSync JWKS Configuration
**Location:** `apps/powersync-server/config/powersync.yaml`

```yaml
client_auth:
  jwks:
    keys:
      - kid: "fajr-emr-key"
        kty: oct
        k: <REDACTED-generate-with-openssl-rand-base64-64>
        alg: HS256
  audience: ["powersync", "powersync-dev"]
  issuer: https://emr.fajr.org
```

**Key Points:**
- `kid` must match between JWT header and JWKS configuration
- `k` is the base64-encoded JWT secret (same as JWT_SECRET env var)
- PowerSync decodes the `k` value to verify JWT signatures

## Authentication Flow

```
Mobile App Login
    ↓
POST /api/auth/mobile-login
    ↓
Generate JWT with:
    - kid: "fajr-emr-key" ✅
    - Signed with decoded JWT_SECRET ✅
    - sub: user.id ✅
    - 14-day expiry ✅
    ↓
Return token to mobile app
    ↓
Mobile app stores token in MMKV
    ↓
PowerSync fetchCredentials() retrieves token
    ↓
Connect to wss://ws.emr.fajr.org/
    ↓
PowerSync validates JWT:
    - Finds key using 'kid' ✅
    - Verifies signature ✅
    - Checks 'sub' claim exists ✅
    - Validates expiry, issuer, audience ✅
    ↓
✅ Connection successful
    ↓
Begin syncing data
```

## Testing JWT Tokens

### Decode JWT Token
```bash
# Get token from mobile app logs
TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCIsImtpZCI6ImZhanItZW1yLWtleSJ9..."

# Decode header (first part)
echo "$TOKEN" | cut -d. -f1 | base64 -d | jq

# Expected output:
# {
#   "kid": "fajr-emr-key",
#   "alg": "HS256",
#   "typ": "JWT"
# }

# Decode payload (second part)
echo "$TOKEN" | cut -d. -f2 | base64 -d | jq

# Expected output:
# {
#   "sub": "5dddd510-544f-4f37-a75d-4f35053e6057",
#   "id": "5dddd510-544f-4f37-a75d-4f35053e6057",
#   "email": "user@example.com",
#   ...
# }
```

### Verify Token on jwt.io
1. Copy JWT token from mobile app logs
2. Go to https://jwt.io
3. Paste token in "Encoded" section
4. Verify header includes `kid` and payload includes `sub`
5. Paste base64-decoded secret in "Verify Signature" section
