Firstline is an open-source electronic medical records (EMR) system. It's built for mission teams and
clinics that need patient charts, care-team messaging, Telegram-based patient intake and video calls,
running on a server they control.

These docs are for the **IT manager** (or volunteer, or contractor) who sets that server up and keeps it
running. You don't need to be a developer, but you should be comfortable with SSH and a Linux terminal.

<Callout type="warn" title="Read this before using real patient data">
  Firstline is pre-production software. It hasn't had a third-party security audit and isn't certified
  for HIPAA, GDPR or any other regulatory regime. Do your own security review and put the right legal
  and administrative safeguards in place first. See the project's [security
  policy](https://github.com/kessenma/firstline-emr/blob/main/SECURITY.md).
</Callout>

## How a Firstline install fits together

Firstline runs as a set of Docker containers on a single Linux server. You manage them with
[Coolify](https://coolify.io), an open-source, self-hosted platform for deploying apps (a bit like
running your own Heroku). Coolify builds Firstline from its GitHub repository, handles HTTPS
certificates, and gives you a web dashboard for logs, environment variables and redeploys.

You'll be responsible for that server. Coolify does a lot for you, but expect to learn its dashboard,
because that's where you'll do most day-to-day work.
